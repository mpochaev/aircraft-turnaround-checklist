## 1. Таблица переходов для `allowedActions`

### Оборот — `PATCH /turnarounds/{id}` 

| Из | В | Право | Условие | Кнопка |
|----|---|-------|---------|--------|
| `planned` | `in_service` | `turnarounds.service` | Назначенный техник; борт и стоянка не заняты другим оборотом | «Постановка ВС» |
| `in_service` | `ready` | `turnarounds.manage` | Все обязательные операции выполнены, иначе `409 MANDATORY_NOT_DONE` | «Подтвердить готовность» |
| `ready` | `closed` | `turnarounds.service` | Назначенный техник | «Отправление ВС» |
| `planned` | `cancelled` | `turnarounds.manage` | Обязателен `cancelReason`, без него `422` | «Отменить» |

**Дополнительные правила:**
- `technicianId` меняет супервайзер (`turnarounds.manage`) — до отправления.
- Отмена возможна только из `planned`.
- После `closed` оборот доступен только для просмотра.
- Неверный переход → `409 INVALID_TRANSITION`.

### Операция — `PATCH /operations/{id}` 

Значения `allowedActions`: `start`, `finish`, `problem`, `resolve`, `not_required`, `revert`.

| Из | В | Action | Право | Условие |
|----|---|--------|-------|---------|
| `not_started` | `in_progress` | `start` | `operations.execute` | Предшественники `done` или `not_required`, иначе `409 PREDECESSORS_NOT_DONE` |
| `in_progress` | `done` | `finish` | `operations.execute` | Отставание > 10 мин → обязателен `delayCodeId`, иначе `422 DELAY_CODE_REQUIRED` |
| `in_progress` | `problem` | `problem` | `operations.execute` | Обязателен `comment` (`422`) |
| `problem` | `in_progress` | `resolve` | `operations.manage` | Обязателен `comment` |
| `not_started` | `not_required` | `not_required` | `operations.manage` | Только необязательная операция, иначе `422 MANDATORY_OPERATION` |
| `in_progress` | `not_started` | `revert` | `operations.manage` | Исправление старта; обязателен `comment` |
| `done` | `in_progress` | `revert` | `operations.manage` | Исправление завершения; обязателен `comment`; только до готовности оборота (ФТ-37) |

**Общие правила для операций:**
- Все переходы — только пока оборот в статусе `in_service`, иначе `409`.
- Техник имеет `execute` на своих оборотах (прав на свои данные не нужно), супервайзер — `manage`.
- Пустой массив `allowedActions` = кнопок нет.
- Таблица ложится в общий компонент кнопок Алексея, который Ярослав переиспользует в таблице супервайзера.

## 2. Интерфейс расчёта плана

Ярослав сегодня отдаёт Артёму сигнатуру; Артём подключает её к `POST /turnarounds` к 13.11.

### Требования

| Требование | Суть |
|------------|------|
| ФТ-27 | План считается от STA рейса прилёта по длительностям и зависимостям нормативов; одна операция на каждый активный норматив типа ВС |
| ФТ-21, сценарий 26 | Снимок нормативов: при изменении норматива старый оборот не пересчитывается |
| ФТ-29, сценарий 27 | При «Постановка ВС» план пересчитывается от фактического `on_block_at` |
| ФТ-34, контрольный пример 1 | «Не требуется» исключается из цепочки — уборка трапа её не ждёт |
| ФТ-36 | `delayRisk`, если плановое окончание последней операции позже STD |

### Предлагаемая сигнатура

| | Состав |
|---|--------|
| **Вход** | Снимок операций (`code`, `durationMin`, обязательность, `after`); якорь времени (STA или `on_block_at`); статусы «не требуется» |
| **Выход** | `plannedStart` / `plannedEnd` для каждой операции (длиннейший путь по зависимостям); `delayRisk`; список блокирующих предшественников для `allowedActions` |

**Приёмка:** контрольные примеры 1–4 и 7 ПМИ (A320/B777, ПОО, снимок); конкретные ожидаемые времена — в таблице 8 ПМИ.

## 3. `RefApi.activeNorms` и `RefApi.isActive`

**Текущее состояние:** в `RefApi.java` уже объявлены `isActive(String dictionary, long id)` и `activeNorms(String aircraftTypeCode)`, возвращающий `List<Map<String, Object>>` с TODO «заменить Map на запись».

### Что согласовать

| Вопрос | Предложение |
|--------|-------------|
| Тип записи вместо `Map` | `record Norm(operationCode, name, durationMin, mandatory, after)`, где `after` — коды операций (как в справочнике нормативов), не id. Хватает и Ярославу для расчёта, и Артёму для снимка в `ops.operation_exec` |
| Семантика `isActive` | Активность проверяется на момент создания оборота (ФТ-26: борт, стоянка, техник активны; чек-лист по активным нормативам) |

### Главный открытый вопрос

**Тип стоянки и международные рейсы.** Решение закрывает Анна со «Справочниками» и преподавателем, затем передаёт команде (plan.md:35, строка Анны в PDF).

- Если операции зависят от этих признаков, у `activeNorms` появляются дополнительные параметры.
- Это меняет и снимок, и модель данных.
- `activeNorms` / `isActive` с учётом решения нужны к **13.11**.

**Процесс:** «Справочники» меняют `RefApi` только по договорённости с нами (README «Справочников»), поэтому предложение по сигнатуре исходит от нас сегодня.

## 4. Формат ответов и `allowedActions`

### Единый формат

| Аспект | Правило |
|--------|---------|
| Кодировка, ключи | JSON UTF-8, camelCase |
| `id` | Целые числа |
| Даты | `YYYY-MM-DD` |
| Время | `YYYY-MM-DDTHH:MM:SS`, местное, без пояса |
| Пустые значения | `null` и `[]` |
| Неизвестные поля запроса | `400` |
| Списки | `{items, total}` |
| Ошибка | `{error: {code, message, details: [{field, value, message}]}, requestId}` |
| Серверные времена | `actual_start`, `actual_end`, `on_block_at` и т. п. ставит только сервер |

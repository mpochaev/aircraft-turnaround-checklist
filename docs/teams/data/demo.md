# Как запустить систему и проверить работу команды «Данные»

Стенда в песочнице нет, поэтому испытания идут на локальном стенде в Docker. Сервер и база в нём работают в контейнерах Linux, это и есть тестовый стенд для сценариев 53 и 57.

## 1. Запуск

Нужны Git и Docker Desktop. Для демонстрационных данных нужен ещё Python 3.

```bash
git clone https://github.com/mpochaev/aircraft-turnaround-checklist.git
cd aircraft-turnaround-checklist
cp .env.example .env
docker compose -f infra/docker-compose.yml --env-file .env --profile app up -d --build
```

Первый запуск собирает приложение, это занимает 2–3 минуты. Проверка, что всё поднялось (четыре сервиса в состоянии running):

```bash
docker compose -f infra/docker-compose.yml --profile app ps
```

| Что | Адрес | Вход |
|---|---|---|
| Приложение | http://localhost:8080 | sup01, sup02 (супервайзеры), tech07, tech12 (техники), пароль `Demo-2026` |
| Описание API | http://localhost:8080/swagger | |
| Просмотр базы (Adminer) | http://localhost:8181 | система PostgreSQL, сервер `db`, пользователь, пароль и база `checklist` |
| Keycloak | http://localhost:8180/admin | admin / admin |

Если Keycloak у вас запускался до 27.11, загрузите realm заново, иначе не будет отчества и новой страницы входа:

```bash
docker compose -f infra/docker-compose.yml rm -sf keycloak
docker volume rm checklist_kcdata
docker compose -f infra/docker-compose.yml --env-file .env --profile app up -d
```

Остановить всё: `docker compose -f infra/docker-compose.yml --profile app stop`. Команду `down -v` не используйте, она удаляет базу.

### Демонстрационные данные

Трое суток работы SVO, около 150 оборотов в сутки. Нужны для сценария 52 и чтобы экраны были заполнены. Команды выполняются в Git Bash или терминале IDEA:

```bash
python tools/demo-data/generate_demo_data.py --now 11:00
docker compose -f infra/docker-compose.yml exec -T db psql -U checklist -d checklist < tools/demo-data/out/demo_data.sql
```

Сценарии 1–51 по ПМИ выполняются на базе без этого набора.

## 3. Как показать по сценариям ПМИ

Запросы к базе выполняются в Adminer: «SQL-запрос», вставить текст из файла, «Выполнить».

| Сц. | Что сделать | Что должно получиться |
|---|---|---|
| 47 | Под sup01 открыть «Журнал», в поле «Оборот» ввести номер оборота, «Показать». Нажать на запись | все действия по обороту с названиями; нажатие открывает чек-лист оборота |
| 48 | Под tech07 открыть «Профиль», блок «Мои действия за смену». В Swagger под токеном tech07 вызвать `GET /log?userId=1` | в профиле только действия tech07; запрос с чужим `userId` даёт 403 |
| 49 | Выполнить по одному запросы из `tools/pmi/49_log_protection.sql` | каждый запрос отклонён базой с текстом «Записи журнала изменять нельзя», «…удалять нельзя», «Журнал очищать нельзя» |
| 50 | Выполнить `tools/pmi/50_block_log_on.sql`, под tech07 нажать «Завершить» у операции в работе, затем выполнить `50_block_log_off.sql` | ошибка 500, операция осталась «В работе» |
| 51 | Под sup01 открыть «История», выбрать период и тип A320 | закрытые обороты и показатели; ручной расчёт тем же запросом в `docs/metrics.md` даёт те же числа |
| 52 | Загрузить демонстрационные данные, под sup01 открыть «Обороты» на день набора. В браузере F12, вкладка «Сеть» | `GET /turnarounds` на 150 оборотов около 0,1 с (норма 2 с), «Завершить» около 0,05 с (норма 1 с) |
| 53 | Под tech07 завершить операцию. Сравнить время в чек-листе, в базе (`select actual_end from ops.operation_exec order by actual_end desc nulls last limit 1`) и на часах | время совпадает, московское; `docker compose -f infra/docker-compose.yml exec app date` показывает MSK |
| 55 | `docker compose -f infra/docker-compose.yml --env-file .env run --rm backup now`, затем `… run --rm backup restore <файл из infra/backup/data>` и запрос из `docs/backup.md` в базах `checklist` и `checklist_restore` | числа оборотов, операций, записей журнала и версия схемы совпадают |
| 56 | Выполнить шаги из `tools/pmi/56_old_data.sql` по порядку | удалены обороты и журнал старше 3 лет, данные за последний месяц и справочники на месте |
| 57 | Чек-лист техника открыть в Яндекс Браузере на планшете или в Chrome F12 → режим устройства 1280 × 800; таблицу оборотов в Chrome на мониторе 1280. Версии ПО: `docker compose -f infra/docker-compose.yml exec app cat /etc/os-release` и `select version()` в Adminer | кнопки не меньше 48 пикселей (1,27 см), шрифт 16 пикселей; сервер Linux (Ubuntu), PostgreSQL 16 |

## 4. Как убедиться, что всё сделано

1. Автотесты: `./mvnw verify` (на Windows `mvnw.cmd verify`), Docker должен быть запущен. Результат: 213 тестов, BUILD SUCCESS. Та же сборка проходит в GitHub на каждом пулреквесте (вкладка Actions).
2. Задание команды и что сделано по неделям: [README.md](README.md) в этой папке.
3. Документы в `docs/specs`: «Модель данных» 1.3 описывает все таблицы и миграции, протокол испытаний готов к заполнению.
4. Сценарии из раздела 3 показываются вживую за 15–20 минут.

## 5. Что зависит не от нас

Чтобы приняли весь проект, остались задачи других команд:

- «Бизнес-логика»: на сервере нет переходов оборота «Постановка ВС», «Подтвердить готовность», «Отправление ВС» (`PATCH /turnarounds`), не подключены «Решено» и «Исправить отметку». Без этого не проходят сценарии 27, 33, 35–37, 41.
- «Авторизация»: ПМИ (сценарии 1–8) и раздел 5 спецификации API всё ещё описывают вход без Keycloak; `POST /me/requests` отвечает 202 вместо 201.
- «Справочники»: нет миграции новой версии справочников для сценария 54.

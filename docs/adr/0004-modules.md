# ADR-0004. Монолит из модулей, границы проверяет Spring Modulith

Статус: принято (монолит выбран в «Описании архитектуры», таблица 5). Инструмент проверки предложен 27.10.2026.

## Контекст

Одно приложение пишут четыре команды. В «Описании архитектуры» (раздел 4) записаны правила: модуль не лезет в чужие таблицы и чужой код, а общается через открытый интерфейс. На паре 23.10 преподаватель просил согласовать протоколы взаимодействия между модулями. Если правила не проверять автоматически, через месяц их нарушат случайно.

## Решение

- Каждая команда владеет пакетом первого уровня: `auth`, `ref`, `ops`, `log`. Общий код лежит в `shared`.
- Открытый интерфейс модуля лежит в корне пакета: `AuthApi`, `RefApi`, `AuditLog`. Пакеты `web` и `internal` закрыты.
- Spring Modulith проверяет это в тесте `ModularityTests`, тест идёт в CI на каждый пулреквест.
- Правило про базу (пишем только в свою схему, читаем в SELECT только `ref.*` и `auth.app_user`) тест не ловит. Его проверяют на ревью, а файлы миграций смотрит команда «Данные».

## Последствия

- Модули можно разрабатывать параллельно. Если модулю «Обороты» нужен новый метод справочников, команда заводит задачу на «Справочники».
- Позже модуль можно вынести в отдельный сервис: его интерфейс уже описан.

# ADR-0003. Страницы на HTML и JavaScript без сборки, своя дизайн-система

Статус: предложено 27.10.2026, ждёт обсуждения в чате лидеров.

## Контекст

На паре 23.10 договорились, что нужен общий дизайн, иначе каждая команда сделает интерфейс по-своему. Экраны работают через REST API, это записано в спецификации. Писать экраны будут те же люди, что пишут сервер. Опыт у них в основном с Java, в группе нет людей, которые занимаются только фронтендом.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| HTML и JavaScript (модули ES) без сборки, свои стили | ничего ставить не надо, страницы лежат в том же приложении и разворачиваются одним jar, правка видна после обновления страницы | компонентов меньше, чем в библиотеках, повторяющийся код выносим в `js/` сами |
| React или Vue с библиотекой компонентов | готовые компоненты, удобно для больших интерфейсов | Node.js и сборка, отдельное развёртывание, порог входа для тех, кто писал только на Java |
| Thymeleaf (страницы на сервере) | знаком по курсу Spring | расходится со спецификацией: экраны работают через REST API, автообновление и кнопки всё равно потребуют JavaScript |

## Решение

Первый вариант. Экранов 11, все табличные, сложного состояния нет.

- Стили: `static/css/tokens.css` (цвета и размеры с макетов) и `static/css/ui.css` (компоненты). Витрина: `/styleguide.html`.
- Общий JavaScript: `js/auth.js` (вход через keycloak-js), `js/api.js` (запросы и ошибки), `js/layout.js` (шапка и меню по правам), `js/format.js` (время, статусы, цвета ячеек).
- keycloak-js лежит в репозитории (`static/vendor/keycloak.js`), страницы не зависят от CDN.

## Последствия

- Каждая команда делает страницы своего модуля по образцу готовых. Правила оформления: [design-system.md](../design-system.md).
- Если группа решит перейти на React, API и дизайн-токены останутся прежними, переписать придётся только страницы.
